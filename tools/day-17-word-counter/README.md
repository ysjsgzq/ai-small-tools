# Day 17 · 字数统计工具

投稿按字数收版面费、公文有字数红线、作文卡 800 字——但「字数」到底怎么算，每个口径都不一样。把文字贴进来，六个口径一次算清。浏览器本地计算，不联网、不上传。

## 六个口径

| 口径 | 规则 |
| --- | --- |
| Word「字数」（主指标） | 汉字与中文标点逐字计 1；英文按词计 1；数字串计 1。与 Word 状态栏「字数」一致：`12.5` 算 1 个、`e-mail` 算 1 个、`a@b.com` 算 1 个 |
| 字符数（计空格） | 全部字符数，版面费/公文红线常用 |
| 字符数（不计空格） | 去掉所有空白后计数 |
| 中文汉字数 | 不含中文标点的纯汉字数（纯汉字口径） |
| 英文单词数 | 连字符/撇号/@/点相连的词不拆开 |
| 数字串数 | 含小数点与内部连字符的连续数字 |

## 使用

单文件静态页面，无依赖、无网络请求。

```bash
# 在仓库根目录启动本地服务
python3 -m http.server 4173
# 浏览器打开
# http://localhost:4173/tools/day-17-word-counter/
```

Windows / macOS / Linux 通用，也可直接双击 index.html 打开。

## 踩坑记录（真实发生）

1. **v1 把「价格 12.5 元」里的数字算成 2 串**（`12` 和 `5` 被小数点切开）——数字串规则补上小数点与内部连字符。
2. **测试期望值自己都数错了两回**：`AI帮我做2026` 我先口算成 4（真值 5，`帮我做` 是 3 个汉字）；T10 的 43 个字符我数成 42——两处都是复查分词明细后修正的，工具全对。数数这件事，人肉才是不可靠的那一环，正好是这篇工具存在理由的现场证明。

## 边界说明

- Word 口径按微软官方对「字数」的通行规则实现（东亚字符逐字、西文按词）；个别版本对连字符词的归属可能有±1 差异。
- 全角/半角标点均按上述规则处理；emoji 等代理对字符按 2 计入字符数（JS 字符串长度语义）。
- 本地计算，关闭页面即忘。
