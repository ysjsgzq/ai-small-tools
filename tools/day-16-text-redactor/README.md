# Day 16 · 文字敏感信息打码工具

把要外发的文字贴进网页，自动识别并打码：手机号（含 +86/86 前缀）、18 位身份证号、银行卡号、邮箱。全程浏览器本地正则处理，不联网、不上传、不存储。

## 识别规则

- 手机号：`1` 开头第 2 位 3-9 的 11 位数字；`+86` / `86` 前缀原样保留，只对本体 11 位打码（保留前 3 后 4）。
- 身份证：18 位且第 7-14 位为合法出生日期；保留前 3 后 4。15 位老式证件暂不识别（边界如实标注）。
- 银行卡：13-19 位数字（允许空格/横线分组）**且通过 Luhn 校验**才认定，保留前 4 后 4——订单号、快递单号等绝大多数过不了 Luhn，不会被误伤；`86+合法手机号` 形态的 13 位串优先按手机号处理。
- 邮箱：只打码 @ 前的本地部分（保留首字符 + `***`），域名不动；邮箱命中区间受保护，内部的手机号样数字不会被二次打码。
- 实现要点：先收集全部命中区间，按 邮箱 > 身份证 > 银行卡 > 手机号 的优先级去重叠，再从右往左替换；所有数字类正则带前后不得是数字的边界守卫——无分隔的长串数字宁漏勿误。

## 使用

单文件静态页面，无依赖、无网络请求。

```bash
# 在仓库根目录启动本地服务
python3 -m http.server 4173
# 浏览器打开
# http://localhost:4173/tools/day-16-text-redactor/
```

Windows / macOS / Linux 通用，也可直接双击 index.html 打开。

## 踩坑记录（真实发生）

1. **v1 手机号正则误伤身份证**：朴素正则把身份证内部的 `19900307775` 当手机号打残（`110101199****77758`），且身份证计数为 0——改为带数字边界守卫的正则 + 区间优先级去重叠。
2. **v1 银行卡误伤订单号**：纯位数判断把 16 位订单号当卡打码——加 Luhn 校验后订单号（Luhn 不过）不再误伤，同时支持了空格分组的真卡号。
3. **v1 邮箱被二次打码**：先打手机号再处理邮箱，`abc13812345678@qq.com` 变成 `abc138****5***@qq.com`——邮箱区间优先保护。
4. **v2 的 86 前缀坑**：`8613812345678` 碰巧通过 Luhn，被银行卡优先级抢走打成 `8613****5678`——卡号候选排除 `86+合法手机号` 形态，复测通过。

## 边界说明

- 打码是降低识别度，不等于加密；涉及法定匿名化要求的场景请另行评估。
- 无分隔符的长串数字中嵌着的手机号识别不到（宁漏勿误），请人工补查。
- 15 位老式身份证暂不识别。
