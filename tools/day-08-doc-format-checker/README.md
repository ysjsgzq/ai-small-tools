# Day 08 · 文档格式体检器

标书、论文、申报材料最怕格式漏项：内容写得好只是及格，格式错一项可能直接出局。这个工具把散落在招标文件各处的格式要求拆成结构化检查项，再逐条核对文档，输出一份能处理的体检报告。

与前四个工具不同，这是一个 **Agent Skill**：由 `SKILL.md` 指导 AI 完成整条流程（拆要求 → 跑脚本 → 出报告），脚本只负责其中可确定的部分。

## 用法

```bash
python3 scripts/docx_format_check.py --doc 标书.docx --reqs requirements.json --out report.md
```

仅依赖 Python 3 标准库。`requirements.json` 的写法见 `assets/requirements.example.json`，由四字段组成：检查对象 · 目标属性 · 期望值 · 来源位置。

## 报告长什么样

对 `assets/test-bid.docx`（一份埋了 6 处格式错误的测试标书）运行示例要求，结果：

- **不符合（3 项）**：字体——第 2 段直接设置的宋体 + 第 3 段藏在样式表里的宋体；字号——第 4 段小四、第 9 段三号；行距——第 6 段固定值 20 磅、第 8 段 1.5 倍行距。逐条给出「第几段、当前值、要求值、来源位置」。
- **需人工确认（2 项）**：纸张（文档未读取到页面设置，如实标注而不是当作通过）、签字盖章（实体要求，机器无法检查，附原话）。
- **符合**：无差异的检查项保留记录。

## 设计原则

- **只报告事实，不修改文档**：改字号会牵动分页、目录、交叉引用，是否修改由人决定。
- **三状态**：符合 / 不符合 / 需人工确认。「没查到」不等于「没问题」。
- **样式继承**：生效格式 = 直接格式 > 段落样式链 > 文档默认，样式表里的错误同样能查出。
- **本地解析**：文档与结果都不离开本机。

## 已知边界

定位精确到段落（页码需要排版引擎）；未覆盖页眉页脚、表格内部、目录域、修订记录；打印、装订、签章只能提醒人工确认。
